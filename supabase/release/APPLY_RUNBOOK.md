# COCR — Runbook تطبيق الحزمة على Supabase (production)

الحزمة دي **اتجرّبت فعليًا** على نسخة Postgres محلية مطابقة للداتابيز الحية (نفس الجداول، الـ policies الـ 106، الـ triggers، الـ default privileges، وبيانات بحجم الإنتاج). مفيش أي حاجة اتطبّقت على Supabase.

## 1) قبل ما تبدئي (3 خطوات، حوالي 10 دقايق)

1. **Backup.** Supabase → Database → Backups (لو الخطة فيها). لو مفيش: Table Editor → Export CSV للجداول دي: `profiles`, `course_enrollments`, `certificates`, `mentor_applications`, `projects`, `project_reviews`, `course_submissions`, `submission_feedback`, `course_sessions`, `catalog_lesson_progress`, `opportunities`.
2. **Preflight.** شغّلي `PREFLIGHT_before_applying.sql` (قراءة فقط) وابعتيلي النتيجة. بيأكّد إن الداتابيز لسه مطابقة للأودتات، وبيجاوب هل `pgcrypto` في schema `extensions` (يعني bug إصدار الشهادات حقيقي دلوقتي).
3. **مفيش لازمة تقفلي الموقع.** كل ملف `begin … commit` (كله أو مفيش)، ومفيش أي ملف بيمسح أو يعدّل صف موجود (الاستثناء الوحيد: عمود `status` الجديد على `course_enrollments` بيتملى `completed` لصفّين بس، وده عن طريق backfill في 0025 ومش بيفعّل أي trigger).

## 2) الترتيب

كل ملف: افتحيه، انسخي المحتوى كله، الصقيه في SQL Editor، **Run**، لازم يطلع Success. لو ظهر أي error **وقفي وابعتيلي نص الخطأ** (الملف مبيسيبش نص تطبيق).

| الموجة | الملفات بالترتيب | بتعمل إيه |
|---|---|---|
| **W1 — تقفيل ثغرات حيّة** | `0016b_emergency_lockdown` → `0016c_repair_drift` → `0020` → `0021` → `0022` → `0023` → `0024` | تقفل الثغرات المؤكّدة (views قابلة للكتابة، self-approve مينتور/ولي أمر، نشر مشروع بدون مراجعة، تزوير completed_at، mentor_ratings)، وتصلّح bug الشهادات + جدول `saved_items` الناقص |
| **W2 — إشعارات وإنجازات** | `0017` → `0018` → `0019` | إنجازات، إشعارات (بتتبنّى جدول `notifications` الحي وتضيف عليه `link` و`read_at`)، بايبلاين الفرص |
| **W3 — نظام الدفعات** | `0025` → `0026` → `0027` → `0028` → `0029` → `0030` → `0031` → `0032` → `0033` → `0034` | Course ← Curriculum ← Cohort ← Enrollment ← Sessions/Attendance/Quiz/Task ← Graduation ← Completion ← Certificate |
| **W4 — قفل الصلاحيات** | `0035_final_privilege_sweep` | anon مبيكتبش، الدوال الداخلية مقفولة، default privileges آمنة |

**بعد كل موجة** شغّلي `VERIFY_after_each_wave.sql` (قراءة فقط). كل صف `passed = true` للموجة اللي خلصتيها ولكل الموجات اللي قبلها. أرقام النجاح المتوقعة:

| بعد | W1 | W2 | W3 | W4 |
|---|---|---|---|---|
| W1 | 16/16 | 0/5 | 1/12 | 0/5 |
| W2 | 16/16 | 5/5 | 1/12 | 0/5 |
| W3 | 16/16 | 5/5 | 12/12 | 0/5 |
| W4 | 16/16 | 5/5 | 12/12 | 5/5 |

(الأرقام دي من تشغيل فعلي على النسخة المحلية. الفحوصات اللي لسه ماطلعتش true بتتوقّع موجات لسه ماتطبّقتش — ده طبيعي.)

**ملحوظة عن W1:** `0016b` لوحده مستقل وآمن، وأنصح بتطبيقه **فورًا** حتى قبل الباقي — الثغرة اللي بيقفلها (كتابة/مسح بروفايلات وسيشنز من غير تسجيل دخول) موجودة دلوقتي.

## 3) اختبار سريع بعد W4 (5 دقايق، من المتصفح)

1. زائر من غير تسجيل: الصفحة الرئيسية، الكورسات، الفرص، `/verify/<رقم شهادة>` بيشتغلوا.
2. طالب: يسجّل دخول، الداشبورد، يبدأ كورس، يخلّص درس، الجرس (الإشعارات)، البروفايل، حفظ فرصة.
3. مينتور معتمد: `/mentor` بتفتح، بناء كورس draft بيتحفظ.
4. ليدر: `/admin` بتفتح، طلبات المينتورز، مراجعة الكورسات.

## 4) لو حصل مشكلة

- **W3 (الدفعات):** `ROLLBACK_cohort_system_0025_to_0034.sql`. اتجرّب: بيرجّع الـ schema والـ policies والـ functions والـ triggers **مطابقة تمامًا** لحالة ما قبل 0025، ويرفض يشتغل لو فيه أي داتا حقيقية للدفعات (عشان مايمسحش شغل ناس).
- **W1 / W2 / W4:** مفيش rollback عمدًا. W1 و W4 تقفيل أمان (الرجوع = فتح الثغرات تاني)، و W2 additive. أي مشكلة فيهم بتتصلّح بـ migration جديدة للأمام، والـ backup موجود.

## 5) اللي اتجرّب فعليًا (النسخة المحلية)

- السلسلة كاملة (21 ملف) بتتطبّق بدون أخطاء، **ومرتين** (idempotent).
- **138 اختبار** رحلة كاملة + هجمات بأدوار حقيقية (مينتور، مينتور تاني، طالب، طالب من دفعة تانية، ستاف، زائر): مسار الإتمام كله من إنشاء الكورس لحد الشهادة والتحقق العام، وكل محاولة تخطّي (نشر ذاتي، تخطّي مراجعة، دخول دفعة كاملة/draft، تسرّب بين دفعات، مفتاح إجابات الكويز، تعديل مشروع معتمد، استدعاء دوال داخلية).
- **صفر regressions** في 38 فحص للمسار القديم (قبل/بعد).
- **الداتا:** 14 enrollment، شهادتين، 5 مينتورز، 4 مشاريع منشورة، تسليمين، سيشن — كل الأعمدة الأصلية متطابقة بعد التطبيق، ولا صف اتمسح، والـ 2 المكتملين اتحوّلوا `completed` بس.

## 6) الحدود (لازم تعرفيها)

- **الاختبار على Postgres 18 (محرك محلي)، مش Supabase نفسها** (Supabase على 15/17). SQL المستخدم قياسي ومفيش feature خاصة بـ 18، بس ده فرق حقيقي.
- **مفيش اختبار تزامن حقيقي** (طالبين على آخر مقعد في نفس اللحظة): المحرك المحلي اتصال واحد. الحماية معتمدة على `SELECT … FOR UPDATE` (مراجَعة كود، مش مجرّبة تحت ضغط).
- **طبقة PostgREST/الـ API ما اتجرّبتش**، بس الـ RLS والصلاحيات اتجرّبوا كأدوار `anon`/`authenticated` (نفس اللي PostgREST بيعمله).
- الجداول القديمة غير المتتبّعة (tasks, resources, sessions, …) اتعملت لها stub بحسب الأودت؛ فيه أجزاء منها ما اتفحصتش (دي مش بتتلمس في الحزمة أصلًا، بس ده مصدر ثقة أقل).
- **الواجهة:** مفيش صفحات طالب للدفعات لسه (مقصود — مفيش UI في الأودت). الـ backend جاهز ومجرّب.

## 7) قرارات اتسجّلت

- الطالب يشوف درجات الـ Rubric بتاعة مشروع تخرّجه (قرارك).
- سيشن **ملغية** مش بتتحسب حضور: المنتور لازم يجدول سيشن جديدة لنفس القالب. الإتمام بيدوّر على سيشن مكتملة لكل قالب إجباري.
- المنهج **بيتقفل** أول ما أي دفعة تتنشر على الكورس.
- مشروع التخرّج **بيتقفل** بعد الموافقة.
- مفتاح إجابات الكويز بيظهر للطالب **بعد أول محاولة** (مراجعة بعد التسليم). لو عايزة الكويز يفضل مقفول أكتر، ده قرار منتج ينفع نغيّره بعدين.
- المنتور هو نقطة الثقة الوحيدة في الحضور واعتماد مشروع التخرّج. الحماية: الليدر يقدر يسحب أي شهادة (`revoke_certificate`)، والقرارات append-only ومتسجّلة باسم المراجع.
- **قاعدة جديدة بعد 0035:** أي function جديدة لازم `GRANT EXECUTE` صريح، وأي جدول/view عام للقراءة لازم `GRANT SELECT` صريح لـ anon. الافتراضي بقى "مفيش وصول".

## 8) اللي مش في الحزمة (مفتوح، مش مخفي)

- `guardian_approvals` و `consents` و `profile_sensitive`: اتقفل الإدخال بحالة approved، لكن لسه ما اتراجعش منطق الموافقة الكامل (خارج نطاق الأودت ده).
- سياسة `sessions registered read` (نظام sessions القديم) فيها مقارنة غلط (`sr.session_id = sr.id`)، نظام قديم مش مستخدم.
- طالب انسحب من دفعة مايقدرش يرجع لنفس الدفعة (unique).
- لو المنتور الوحيد للدفعة اتحذف حسابه: `course_cohorts.mentor_id ON DELETE RESTRICT` بيمنع الحذف لحد ما الدفعة تتنقل/تتلغي (مقصود).
